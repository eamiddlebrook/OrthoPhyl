## wrapper output dir is confusing for ReLeaf runs
[] wrapper --output-dir looks like "the" output dir, but ReLeaf's actual output lands in the DATABASE dir, not there
    _run_releaf (orthophyl_pipeline_wrapper.py) calls ReLeaf.sh -s <database_dir>/orthophyl_run -- ReLeaf's -s always writes to <storage_dir>/ReLeaf_dir, so output goes inside the matched DB's orthophyl_run, not --output-dir
    _create_releaf_version then versions that ReLeaf_dir INTO the db (v2_releaf_..., repoints `current`) -- the db dir is the durable/versioned state, by design (next ReLeaf run starts from it)
    _phase_aggregation only copies the resulting tree back out to <output-dir>/03_results/trees/releaf/ afterward -- a convenience copy, not the source of truth
    --output-dir only ever holds: logs, routing_decision_*.json, staged input genomes (01_releaf_only/<db>/input_genomes/), and the final report/copy
    confusing because "new output dir" implies all outputs live there; real new tree/alignments are a level removed, inside the db you pointed --database-dir at
    ideas: log explicitly where ReLeaf output actually landed (db dir path) right after _run_releaf finishes; maybe rename --output-dir references/docs to make clear it's "run logs + results copy", not primary output
