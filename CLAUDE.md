# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

OrthoPhyl is an orthology-based phylogenomics pipeline for bacteria (and other datasets) at broad evolutionary scales. It has three layers, from lowest to highest:

1. **`OrthoPhyl.sh`** — the core pipeline. Annotates genomes (Prodigal), runs OrthoFinder, aligns/trims orthogroups, identifies single-copy orthologs, and infers species trees (FastTree / IQ-TREE / RAxML / ASTRAL). This is bash driving external bioinformatics tools.
2. **`ReLeaf.sh`** — "adds leaves" to an existing OrthoPhyl run: places new assemblies into a pre-computed phylogeny using saved HMM profiles instead of rebuilding from scratch. Reuses much of the same function library.
3. **`orthophyl_pipeline_wrapper.py`** — Python orchestrator with three modes: batch (`--input`, routes each assembly to either ReLeaf if it matches an existing database, or OrthoPhyl to download related genomes from NCBI and build a new one), taxon (`--taxon`, same NCBI-download-and-build path for a single named clade), and local-genome (`--genome-dir`, builds a database from genomes already on disk under a user-supplied clade name). This is the newest layer and the focus of the unit/integration test suite.

`README.md` documents the Python wrapper; `README_OrthoPhyl_ReLeaf.md` documents the two shell pipelines. Extended docs live in `readmes/`.

## Running

```bash
# Core pipeline from a directory of genome FASTAs
bash OrthoPhyl.sh -g path/to/genomes -s output_dir -t <threads>

# From pre-annotated CDS + protein dirs (comma-separated, transcripts first)
bash OrthoPhyl.sh -a path_to_transcripts,path_to_prots -s output_dir -t <threads>

# Rigor presets override most conflicting params (fast | medium | full)
bash OrthoPhyl.sh -g genomes -s out -R full -t <threads>

# Built-in test datasets (mutually exclusive with -g/-a/-s)
bash OrthoPhyl.sh -T TESTER_fasttest -t <threads>   # small orchid chloroplast set, fastest
bash OrthoPhyl.sh -T TESTER -t <threads>            # full bacterial genomes
bash OrthoPhyl.sh -T TESTER_chloroplast -t <threads>

# End-to-end smoke test (OrthoPhyl then ReLeaf on fasttest data)
bash test.sh <threads> <num_for_OrthoFinder>

# Python wrapper (routing + DB management)
python orthophyl_pipeline_wrapper.py --input assemblies.tsv --database-dir databases/ --output-dir results/ --threads 32

# Python wrapper: build a database from genomes already on disk (QC runs by default)
python orthophyl_pipeline_wrapper.py --genome-dir path/to/fastas --clade-name MyIsolates \
  --database-dir databases/ --output-dir results/ --threads 32
```

Run `bash OrthoPhyl.sh -h` for the full flag list (defined in `script_lib/arg_parse.sh`).

## Testing

The Python layer has pytest suites; the shell pipelines are covered by integration tests that actually run the tools.

```bash
conda activate orthophyl          # provides pytest + all bioinformatics tools

pytest tests/                      # unit tests (subprocess mocked, run in seconds)
pytest tests/unit/test_router.py -v   # a single module
pytest tests/ -m "not slow"        # skip network/long tests
pytest tests/ --cov=. --cov-report=term-missing

pytest -m integration -v           # runs REAL OrthoPhyl.sh/ReLeaf.sh (~5-15 min)
ORTHOPHYL_RUN_INTEGRATION=1 pytest tests/integration/   # CI form
```

Integration tests assert topology correctness via Robinson-Foulds distance (RF=0) against reference trees in `TESTER/REFERENCE_TESTER_TREES/`, and auto-skip if tools (iqtree, orthofinder, mafft, hmmbuild/hmmsearch, trimal) are missing.

Note: the target scripts (`assembly_router.py`, `orthophyl_pipeline_wrapper.py`, `OP_database_tool.py`) live at the repo root and in `assembly_router/`, which are not import packages. `tests/conftest.py` loads them by path via `importlib` and exposes them as fixtures (`router_module`, `wrapper_module`, `db_creator_module`). Import them that way in tests, not with `import`.

Container-aware temp handling: set `PYTEST_TMP_DIR` or `TMPDIR` when `/tmp` is read-only (common under Apptainer/Singularity). See `pytest.ini` and `readmes/README_APPTAINER.md`.

## Architecture notes

**`OrthoPhyl.sh` is a thin driver.** Nearly all logic lives in sourced libraries under `script_lib/`. The top-level `MAIN_PIPE()` in `OrthoPhyl.sh` just calls named functions in order (`SET_UP_DIR_STRUCTURE`, `PRODIGAL_PREDICT`, `ORTHO_RUN`, `TRIM`, `SCO_MIN_ALIGN`, `TREE_BUILD`, ...). To understand or change a step, find its function:
- `script_lib/functions.sh` (~1800 lines) — the core pipeline steps.
- `script_lib/functions_addem.sh` + `arg_parse_addem.sh` — ReLeaf-specific ("add 'em") functions and arg parsing.
- `script_lib/arg_parse.sh` — `USAGE` and `ARG_PARSE` for OrthoPhyl.
- `script_lib/run_setup.sh` — `tester` (test-dataset setup), `test_args`, `SET_RIGOR` (the fast/medium/full presets), `control_c` trap.
- `script_lib/bash_utils_and_aliases.sh` — aliases (`shopt -s expand_aliases` required before sourcing).

**Configuration is layered**, applied in this order (later overrides earlier):
1. `control_file.paths` — paths to external programs (ASTRAL jar, catfasta2phyml, Alignment_Assessment) and `conda activate`. Only sourced when NOT in a container (guarded by `$SINGULARITY_CONTAINER`/`$DOCKER`); in containers these are on `PATH` already.
2. `control_file.defaults` — all pipeline parameter defaults (trimming, tree methods, ANI shortlist size, etc.).
3. Command-line args (`ARG_PARSE`).
4. `-c control_file` if given — **overrides the command line**.
5. `SET_RIGOR` if `-R` given — overrides conflicting params.

Use `control_file.user` for local overrides. ReLeaf uses `control_file.ReLeaf.defaults`.

**ANI shortlisting**: if the input has more sequences than `$ANI_shortlist` (default 20, `-n`), OrthoFinder runs on a MASH-selected diverse subset, then genes are propagated to the full set via HMM profiles (`ANI_ORTHOFINDER_TO_ALL_SEQS`, saved in `OG_alignmentsToHMM/`). These saved HMMs are what ReLeaf reuses.

**Output layout** lives under the `-s` storage dir: `genomes/`, `annots_nucls/`, `annots_prots/`, and `phylo_current/` (the working dir, `$wd`), with final trees in `phylo_current/FINAL_SPECIES_TREES/`.

**Python wrapper**: `PipelineWrapper` in `orthophyl_pipeline_wrapper.py` runs in phases (initialization → routing → releaf → orthophyl → aggregation) with checkpoint/resume. It shells out to three scripts in `assembly_router/`: `assembly_router.py`, `OP_database_tool.py`, and `add_releaf_version.py`. These paths are hardcoded in the constructor (`orthophyl_pipeline_wrapper.py:101-105`).

**Large-taxon handling** (`--max-tree-genomes`, default 2000): when a novel taxon downloads more raw genomes than the ceiling, the wrapper caps final tree size. The **default** is **diverse subsampling** — `python_scripts/subsample_genomes.py` sketches all genomes once (`mash sketch`, linear) then greedily picks the most-diverse `--subsample-size` (default 500) via farthest-point (max-min) selection, one `mash dist` call per pick (O(n·N) time, O(n) memory — no dense matrix, scales to huge taxa). Query/must-keep genomes seed the pick so they're always retained. `_subsample_genomes` stages the selected FASTAs into `<orthophyl_dir>/subsample/<taxon>/selected/`, which then flows through the normal single-tree QC+build path. The `greedy_maxmin(names, dist_fn, target, seed_names)` core is pure (inject a distance oracle to unit-test without mash), mirroring `partition_matrix`.

The **partition/megatree** path is opt-in via `--megatree`. Instead of subsampling an oversized taxon down to one tree, it MASH-partitions the raw set into subclades named `<Taxon>_1`, `<Taxon>_2`, …, builds a full tree for **every** subclade, builds a small BACKBONE tree from a few diverse reps per subclade, and GRAFTS each subclade's full tree onto its reps in the backbone — one merged tree containing every genome. `_run_megatree` orchestrates it; the merged tree + conflict report land in `03_results/trees/orthophyl/<taxon>_megatree.nwk` / `_megatree_conflicts.json`. Key points:
- **Engaged only when raw count > `--max-tree-genomes`** and `--megatree` is set; otherwise it collapses to the normal single-tree build. Not mutually exclusive with subsampling (subsample is the default when `--megatree` is absent).
- **Partition happens *before* QC.** The download step is split into `gather_filter_asms.sh --download-only` (raw FASTAs land at `<dl>/assemblies_all.TMP/*.fna`, queries staged as clustering leaves) and a per-subclade `gather_filter_asms.sh --qc-only` (CheckM2 runs here). CheckM2 therefore runs only on genomes that will enter a tree. Neither flag alone changes the script's default combined behaviour.
- **Clustering** lives in `python_scripts/subclade_partition.py`: `mash triangle -k 17 -s 5000 -E` (params MUST match everywhere), scipy `average`-linkage (UPGMA), recursive size-bounded split (megatree passes `--max-size self.subclade_size`, default 150), deterministic size-desc/name numbering. It writes `partition_manifest.json`, a per-subclade `.msh` sketch, and a `.members.txt`. Do NOT reuse `ANI_genome_picking.py` (wrong divergence floor / merge logic).
- **Grafting** lives in `python_scripts/megatree_graft.py` (pure ete3, unit-tested by injecting newick strings). `graft(backbone, subclade_trees, rep_map, min_support)` does MRCA-replace with a monophyly check (non-monophyletic reps → best-effort anchor-graft, foreign leaves preserved, flagged). `induced_conflicts(...)` flags high-support (≥ `--conflict-min-support`, default 90) bipartition disagreements between a subclade tree and the backbone — flagging only, NOT resolution (reconciliation is future work). Backbone reps = `min(subclade_size, --backbone-reps)` (default 5) per subclade via that subclade's MASH greedy max-min. The taxon DB is created from the **backbone** run so ReLeaf has a coherent HMM set. `--taxon` create mode and `--genome-dir` local mode both take the same path (no query → all subclades built; local mode's DBs carry `taxonomy_source='user_supplied'`).
- **Total-genome guardrail** (`--max-total-genomes`, default 25000): the *partitioner* builds an all-vs-all MASH distance array kept in scipy's CONDENSED (1-D, upper-triangle-only) form throughout — `parse_mash_edges`/`partition_matrix`/`_merge_tiny_clusters` in `subclade_partition.py` never materialize a dense `NxN` matrix (see `condensed_index`), which would roughly double peak memory for no benefit. Still O(n²) in both time and memory (measured ~8 hours wall-clock and ~22 GB RAM at n=75k, 12 threads). `_enforce_total_genome_ceiling` hard-stops the megatree path above the ceiling rather than running for hours or OOM-killing the node. The **default subsample path never builds this array and is not subject to this check** — it handles arbitrarily large taxa. A query-neighborhood-mode ToDo exists for taxa too large even for this path, sidestepping the O(n²) cost entirely.
- **Routing** (`assembly_router.py`) has three decisions: **ReLeaf** (matches an existing DB), **OrthoPhyl** (novel taxon), or **OrthoPhyl_subclade_build** (query matched a lazily-registered subclade that has no tree yet — build it, then ReLeaf). Every megatree DB shares its parent's taxonomy string with its siblings (the backbone plus every `<Taxon>_N` subclade), so a query can tie at the same specificity across several DBs; `route_assembly` disambiguates ties by `--placement` and MASH:
  - `--placement subclade` (default): among tied subclade DBs, sketch the query (`mash sketch -k 17 -s 5000`, same params as `subclade_partition.py` — `MASH_K`/`MASH_S` module constants in `assembly_router.py` MUST match) and pick the nearest via `mash dist` (`_route_subclade_by_mash` / pure `pick_nearest_subclade`, ties broken by ascending `clade_name`). Falls back to the backbone DB if no subclade sketch is usable.
  - `--placement backbone`: routes straight to the tied parent's `is_backbone` DB (the sparse megatree overview tree) with no MASH call.
  - A DB with `is_subclade=True` and `built=False` (registered but never built — see below) yields `OrthoPhyl_subclade_build` instead of `ReLeaf`, carrying the subclade's own `clade_taxonomy` as `subclade_taxonomy` (NOT the query's) so a later rebuild doesn't overwrite it.
- **Lazy build-on-demand** (`--megatree-lazy`, opt-in, off by default, implies `--megatree`): at partition time, a subclade with no query assigned to it is only *registered* (`OP_database_tool.py --register-only`, requires `--is-subclade`) rather than getting its own full tree built — `built=false`, a placeholder `phylogeny.nwk`, no `orthophyl_run` symlink, `genome_list.txt` sourced from the subclade's `members_file`. Its sketch/members/`source_genome_dir` are recorded so a later query that MASH-matches it can trigger an on-demand build (`_register_lazy_subclade` → `_phase_subclade_build`/`_process_subclade_build` → `_build_subclade(force=True)`, which promotes the placeholder to `built=true`). Registration and build use *separate* checkpoint keys (`register_<name>` vs `database_<name>`) — sharing one key would let `--resume` mistake a placeholder for a finished build. Without `--megatree-lazy`, every subclade is still built up front (the pre-existing default).
  `_register_lazy_subclade` ALSO QCs the subclade and stages a few diverse backbone reps into `backbone_dir` immediately — only the subclade's own full tree is deferred. This matters because a `--taxon` create-mode run has no query *anywhere*, so every subclade's `queries_here` is empty and every one gets lazily registered; without this, the backbone (built from pooled subclade reps) would get zero input genomes, `OrthoPhyl.sh` would silently build a tree from nothing, and `megatree_graft.py` would crash on the resulting missing tree file two steps later — a real bug fixed by this. `_run_megatree` also fails fast with an explicit `RuntimeError` if `backbone_dir` would still be empty after registration (e.g. every subclade's QC drops all members), and skips the grafter subprocess entirely (publishing the backbone tree directly as the megatree, with an empty `[]` conflict report) when there are zero subclade trees to graft — `megatree_graft.py --subclade` is `required=True`, so a zero-subclade call would otherwise be rejected by argparse.
- **HMM reuse** (`--megatree-hmm-reuse`, opt-in, off by default, implies `--megatree`): instead of every subclade running its own independent OrthoFinder orthogroup inference, give every subclade the **backbone's** orthogroup HMMs. Requires reversing the default build order — the backbone (which produces `OG_alignmentsToHMM/hmms_final/`) must exist before any subclade build, so `_build_megatree_subclades_hmm_reuse` QCs every subclade and pools backbone reps first, builds the backbone, then builds each subclade passing `--hmm-assign-dir <backbone's hmms_final/>` to `OrthoPhyl.sh`. That flag (`script_lib/arg_parse.sh`/`functions.sh`'s `HMM_ASSIGN_FROM_EXTERNAL`) skips `ORTHO_RUN`/MASH-shortlisting entirely: it runs `HMM_search` (reused from `functions_addem.sh`, the same mechanism ReLeaf uses) against the given HMM dir, aligns each assigned orthogroup fresh with plain `mafft --quiet` (NOT ReLeaf's extend-only `ADD_2_ALIGNMENTS`/`mafft --add --keeplength`, since there's no prior subclade alignment to extend), and feeds the result into the unmodified `TRIM`/`SCO_MIN_ALIGN`/`TREE_BUILD` pipeline — so each subclade still computes its own alignment/trim/tree model, only orthogroup identity is shared. OGs with no hits in a subclade are logged (not errored) to `hmm_assign_unmatched_OGs.txt`. Falls back to the default independent-build order (with a warning) if the backbone's rep count never crosses `--ani-shortlist`, so `hmms_final/` never materializes. Default (`--megatree-hmm-reuse` absent) preserves the exact pre-existing build order/behavior.
  `--hmm-assign-dir` ALSO routes genes that matched NONE of the external HMMs through a real `ORTHO_RUN` on their own by default (`--hmm-assign-leftover-orthofinder`'s behavior, now default-on; disable with `--skip-hmm-assign-leftover`, or the wrapper's `--megatree-hmm-reuse-skip-leftover` for every subclade build in the `--megatree-hmm-reuse` path): instead of just logging them, the leftover genes are pooled per-genome (`hmm_assign_leftover_prots/`) and clustered to find additional orthogroups among themselves — same mechanism a normal small-dataset OrthoPhyl run uses. The result is filtered through `OG_sco_filter.py` (threshold 1) to reject paralog-containing OGs before realigning (unlike the externally-assigned OGs, a fresh OrthoFinder clustering has no paralog guarantee, and `SCO_MIN_ALIGN`'s `ANI=true` branch doesn't check for one — letting a multi-copy OG through corrupts SCO membership and crashes `catfasta2phyml` on mismatched per-genome lengths). Surviving OGs are renamed `OG0000001` → `OG0_LFT_0000001` before landing in `AlignmentsProts/`, avoiding a silent filename clobber against the external HMM set's own OG IDs (OrthoFinder always numbers fresh runs from `OG0000001`, no per-run salt) while still satisfying `SCO_MIN_ALIGN`'s `OG0*` glob.
- Subclade/backbone metadata fields (`is_subclade`, `is_backbone`, `parent_taxon`, `subclade_id`, `built`, `sketch_file`, `members_file`, `source_genome_dir`) load via `config.get()` defaults, so pre-existing databases stay backward-compatible. The megatree backbone DB is written with `is_backbone=true` (via `--is-backbone`) so the router can tell it apart from a dense subclade sharing the same parent-level taxonomy.

**Tree-building speed controls** (`--tree-method`, `--iqtree-model`, `--iqtree-mset`, `--iqtree-fast`, `--iqtree-options`): apply to OrthoPhyl builds only — every one of them (`--taxon`, `--genome-dir`, megatree subclade/backbone builds, novel-taxon builds in batch mode) funnels through the single `_run_orthophyl` call site, which is where these are wired in; ReLeaf placement (`_run_releaf`) is untouched. `--tree-method` maps to OrthoPhyl.sh's `-p` (`iqtree`/`fasttree`/`"fasttree iqtree"`). Any `--iqtree-*` flag makes `_tree_control_file` write a one-line control file overriding `IQtree_CDS_speciestree_options` (CDS only — the wrapper always passes `-o CDS`) and passes it as `-c`, exploiting the fact that OrthoPhyl.sh sources `control_file.defaults` *before* `-c` (`OrthoPhyl.sh:79-116`) — so the file can append to the existing default via a literal `$IQtree_CDS_speciestree_options` reference rather than needing to know its contents. `--iqtree-options` replaces that base outright instead of appending. `--iqtree-model` (skip ModelFinder with a fixed model, the single biggest IQ-TREE speedup) and `--iqtree-mset` (constrain which models ModelFinder tests) are mutually exclusive. `--tree-method fasttree`/`both` logs a warning: ReLeaf can't yet extend a FastTree species tree (`functions_addem.sh`'s `ADD_2_fasttree` is unfinished), and FastTree branch support is on a 0–1 scale so `--megatree`'s `--conflict-min-support` (90-scale) never flags a FastTree subclade/backbone conflict. `--iqtree-fast` is rejected (both in `__init__` and `main()`, against the same `_DEFAULT_IQTREE_CDS_OPTIONS` constant) unless the base string it appends `--fast` to is free of `-B`/`-bb` — verified against real IQ-TREE 2.2.0.3, which hard-errors ("Ultrafast bootstrap does not work with -fast...") on `--fast` + UltraFast Bootstrap, and the default `IQtree_CDS_speciestree_options` always includes `-B 1000`, so `--iqtree-fast` alone would otherwise crash every run; the fix is pairing it with `--iqtree-options` that drops `-B`/`-bb` (e.g. `--iqtree-options "--symtest --lmap 2000 -t PARS --ninit 2"`).

**Local-genome ingest** (`--genome-dir DIR --clade-name NAME`): builds a routable database from genomes the user already has, instead of downloading from NCBI. `_run_local_genomes_mode` in `orthophyl_pipeline_wrapper.py`:
- **QC runs by default**, skippable with `--skip-qc` (the request explicitly wanted QC on, not off, by default). Skipping sets `qc_applied=false` in the database config and is only ever honored on this path — `_qc_subclade`/the NCBI download path always QC.
- **Taxonomy resolution** (`_resolve_local_taxonomy`) tries, in order: (1) `--clade-taxonomy` verbatim (an escape hatch for a full GTDB string), (2) resolving `--clade-name` against the local NCBI taxdump to render a full lineage, (3) falling back to a bare `<rank>__<name>` (default rank `g`, `--clade-rank`) with a logged warning and a paste-ready `--clade-taxonomy` hint. A name-only fallback taxonomy is **not routable** — `GTDBTaxonomy.is_within_clade` (`assembly_router.py`) compares every rank down to the query's, so upstream `None` ranks never match a fully-specified query. This is why resolution against the taxdump matters, not just cosmetic padding.
- Every input FASTA is normalized to `<stem>.fna` (gunzip `.gz`, symlink otherwise) into a wrapper-owned staging dir — originals in `--genome-dir` are never touched or renamed, because OrthoPhyl.sh rewrites contig names in its `-g` input in place.
- `taxonomy_source` (`"ncbi"` | `"user_supplied"`) and `qc_applied` (bool) are written to every `database_config.json`, both read with `.get()` defaults (`"ncbi"`/`True`) so pre-existing databases stay valid. `assembly_router.py`'s startup log appends `[user-supplied taxonomy: not NCBI-assigned]` for `user_supplied` DBs — provenance is surfaced, not used to gate routing.
- `--genome-dir` + `--megatree` **is supported**: when the staged genome count exceeds `--max-tree-genomes`, `_run_local_genomes_mode` forks into `_run_megatree` exactly like `--taxon` create mode's fork (no query assemblies either way, so every subclade is built/registered immediately). `taxonomy_source='user_supplied'`/`qc_applied=True` are threaded through every DB-creation call `_run_megatree` makes (backbone, every subclade's `_build_subclade`, every `_register_lazy_subclade`) via new optional kwargs on each — defaults keep every existing `--taxon`/`--input` caller byte-identical. `--genome-dir --megatree --skip-qc` together is rejected by `main()` (every subclade/backbone build QCs its own genomes in this path; no `skip_qc` passthrough exists yet).

**Geographic figures** (`--geo`, opt-in): after a tree is published, auto-generates a country-annotated tree + world map via `python_scripts/annotate_tree_by_country.py`, run as a subprocess (`sys.executable`, `QT_QPA_PLATFORM=offscreen`) by the wrapper's `_generate_geo_figures` helper into `<results-dir>/figures/`. Map rendering is plain matplotlib against a bundled, public-domain Natural Earth 110m admin-0 dataset (`python_scripts/data/`) — deliberately not cartopy/geopandas, which pull in proj/shapely/pyproj and fetch coastline data over the network, breaking offline/container runs.
- **Hook sites**: all four tree-publish points — megatree publish, local-genome mode publish, taxon-create-mode publish, and batch `_phase_aggregation` (both novel-taxon and ReLeaf-published trees). `_generate_geo_figures` itself is **non-fatal** (subprocess failure/`OSError` logs a warning, pipeline still returns 0); the only fatal check is a missing `matplotlib`, raised at startup in `_validate_dependencies` when `self.geo` is True, so the user finds out before hours of compute rather than after.
- **Pair lines**: only the top-K closest cross-country genome pairs by patristic distance are drawn (`--geo-top-k`, default 100; `top_k_cross_country_pairs()` — numpy-vectorized per-LCA leaf-depth outer-sum with a bounded max-heap, chunked by rows so memory stays bounded at megatree scale; same-country and Unknown-country pairs excluded). Line alpha is `pair_alphas()`: `alpha = 1 - d/d_max`, so the single most-distant (K-th) pair in the drawn set is fully transparent and the closest is darkest — a lone pair is simultaneously closest *and* K-th and so gets alpha 0, not 1 (only an all-zero-distance set gets the alpha-1 special case).
- **Country resolution** (`load_country_coords()`/`resolve_country_latlon()`) joins Natural Earth label points against `python_scripts/data/country_aliases.tsv` (INSDC `geo_loc_name` names → Natural Earth names or explicit lat/lon) via a **fixed-point multi-pass** loop, not a single pass — a `"country"`-kind alias can point at another alias that is itself only a `"latlon"` entry (e.g. `"Cape Verde" → "Cabo Verde"`) rather than straight at a Natural Earth name, and a single pass is order-dependent on dict iteration order and can silently leave such chains unresolved.
- **Metadata sources**: NCBI-download paths get country data from `all_asm_acc_metadata`'s `geo_loc_name` column for free; its path is persisted on the DB (`OP_database_tool.py --metadata-file`, stored as a path relative to `db_dir`, same convention as `sketch_file`/`members_file`) so later ReLeaf/batch trees can still look it up. `--genome-dir` mode has no NCBI metadata, so `--geo` there requires `--geo-tsv genome_id<TAB>location` — enforced as a hard `parser.error` in `main()`. Supplying `--geo-tsv` or a non-default `--geo-top-k` implies `--geo`, mirroring the `--megatree`-implication pattern.
- **Query highlighting** (default-on in batch mode, `--geo-highlight`/`--geo-query-top-k` elsewhere): `_collect_geo_query_ids` (called right after `_phase_routing()`) pools `assembly_id`/`Path(assembly_path).stem` from every entry in `routing_results['releaf_batch']`, `['orthophyl_batch']`, and `['subclade_build_batch']` into `self._geo_query_ids`, so routed queries are highlighted with no flag needed. `_generate_geo_figures` unions that set with `_parse_id_list(self.geo_highlight)` (shared comma-list-or-file helper, also used by `_must_keep_stems`) — the only path to highlighting in `--taxon`/`--genome-dir` modes, which route nothing. A non-empty union is written to `figures/<label>_highlight_ids.txt` and passed as `--highlight <file> --query-top-k N` to the subprocess; the script matches IDs against each tree's own leaves (`match_highlight_leaves`, via the existing `_candidate_keys` expansion) and silently drops ones absent from that tree. `--geo-highlight`/`--geo-query-top-k` imply `--geo`, same pattern as `--geo-tsv`/`--geo-top-k`.
  Highlighted leaves get bold-red ★ labels on the tree and ★ markers on both maps, each **deliberately offset** from its country's true point (`_query_offset`, hash-based angle like `_jitter` but radius 8° vs 1.5°, with its own hash salt) and linked back by a dashed leader line — this keeps same-country query lines visible instead of collapsing into the jitter cloud. A combined `<label>_geo_query_map.<fmt>` (one map for every highlighted leaf, not one per leaf) draws distance-colored lines from each offset ★ to its top-K nearest genomes by patristic distance (`query_distances`, an O(n) per-query ancestor walk reusing the same depth-based distance algebra as `top_k_cross_country_pairs`, both built on a shared `_node_depths(tree)`), any country including its own, closer = darker (`plasma` colormap). `<label>_geo_query_neighbors.tsv` and `<label>_geo_query_countries.tsv` carry the same data as plain TSVs (not an on-image panel) — the latter covers every country present in the tree, not just the drawn top-K. Leaves with an Unknown/unresolved country still get tree highlighting and TSV rows but are skipped on the maps with a logged warning.
- Future work (not implemented): the BioSample `lat_lon` attribute does not yet feed these figures (`--geo-tsv`/NCBI `geo_loc_name` only) — see **Geo-provenance checks** below, which does extract and use it, but only for flagging, not for figure rendering.

**Geo-provenance checks** (automatic during NCBI genome download for `--taxon`/`--input` novel-taxon builds; flag-only, never drops or relabels a genome): catches a submitter typing their own institution's location into a sample's geolocation fields, a real and otherwise-silent data-entry error.
- **Column contract**: `all_asm_acc_metadata` (and the equivalent viral path in `utils/gather_viral_annots.py`'s `write_metadata_tsv`) is whitespace-split, 13 data columns — `accession species species.strain biosample taxid taxcheck excl geo_loc collected_by sequenced_by biosample_owner asm_submitter lat_lon` — produced by `python_scripts/parse_asm_metadata.py`'s `project_metadata()` from an 11-BS_to_meta-column + 5-appended-biosample-column (`geo, collected_by, sequenced_by, owner, lat_lon`) merged row. Every field goes through `sanitize_field()` (collapse whitespace → underscore, empty → `NA`) so a column can never shift. Cols 1-8 are unchanged from before this feature existed, so `annotate_tree_by_country.py`, `filter_asm_by_taxCheck`'s `$6`, and the wrapper's existing `geo_loc_name` reads (col 8) keep working untouched.
- `utils/gather_filter_asms.sh` runs a new `annotate_geo_provenance` step right after `all_sample_metadata` in `main()`, invoking `python_scripts/geo_provenance.py annotate` and overwriting `all_asm_acc_metadata` with 6 appended flag columns (19 total): `submitter_country, geo_vs_submitter, latlon_country, latlon_vs_geo, submitter_km, latlon_vs_submitter`. The step is non-fatal — a failure warns and leaves the unannotated 13-column file in place, same "geolocation is decorative" tolerance as the rest of the metadata pipeline.
- **Submitter-country matching**: `resolve_submitter_country()` tries `sequenced_by`, then `asm_submitter`, then `biosample_owner`, checking a small editable override table (`python_scripts/data/org_country_overrides.tsv`, for submitters whose name doesn't mention a country — CDC, PulseNet, Sanger, PHE, FDA) before a whole-phrase country-name/alias scan (with `New Mexico`/`New Jersey`/ambiguous-`Georgia` guards). `geo_vs_submitter` is `match`/`differ`/`unresolved`/`no_geo`. The CLI's stderr summary also surfaces submitter orgs whose samples are ≥90% `match` — the "lab-default" fingerprint of a lab that always labels samples with its own country.
- **lat_lon checks**: `parse_lat_lon()` handles INSDC (`"38.98 N 77.11 W"`) and decimal (`"38.98, -77.11"`) BioSample `lat_lon` formats. `country_at()` resolves coordinates via ray-casting point-in-polygon against the same bundled NE 110m dataset the `--geo` figures use, falling back to nearest-vertex within 50 km for coastal points the coarse 110m outline misses; `latlon_country`/`latlon_vs_geo` flag whether that resolved country matches col 8's `geo_loc`.
- **Submitter-location check (opt-in, `--ror-lookup`/wrapper `--geo-ror`)**: resolves the submitting organization's real-world coordinates via the ROR API (`https://api.ror.org/v2/organizations?affiliation=...`, only `chosen: true` results accepted, JSON-cached per org string, network calls injectable for tests and never fatal on failure/timeout). `submitter_km` is the haversine distance from the sample's `lat_lon` to the org's location; `latlon_vs_submitter` is `at_submitter` (≤ `--at-submitter-km`, default 25 km — the strongest leak signal, meaning the "sample" coordinates are literally the lab), `same_country`, `differ`, or `unresolved`. `--geo-ror` is independent of `--geo` (it affects metadata gathering, not figure rendering) and deliberately does NOT imply `--geo`, unlike `--geo-tsv`/`--geo-highlight`/etc.
- Not yet done: `--ror-lookup`/`--geo-ror` resolution only feeds the flag columns, not `resolve_submitter_country`'s offline text scan; a live network smoke test against real NCBI/ROR data.

**Viral annotation** (`--annotator viral`, opt-in; only `--genome-dir` is supported): annotates raw eukaryotic viral assemblies with NCBI **VADR** (model-based classification) instead of Prodigal, falling back to **VIGOR4** (auto-detected reference DB) when no VADR model library classifies the genome. `--taxon`/`--input` novel-taxon builds and `--megatree` reject `--annotator viral` outright — not a missing feature, a mismatched combination: those paths detect viral taxa and get NCBI's existing annotations directly (see below), so there's no raw assembly for VADR/VIGOR4 to run over.
- `python_scripts/viral_annotate.py` does the per-genome work (VADR first, VIGOR4 fallback, header normalization to `<g>_<n>` matching `$trans`/`$prots`); `script_lib/arg_parse.sh`/`arg_parse_addem.sh` already exposed `--annotator`/`--vadr-models`/`--vigor-db`/`--vigor-db-dir` on both `OrthoPhyl.sh` and `ReLeaf.sh` before the wrapper layer existed.
- **Wrapper threading** (`orthophyl_pipeline_wrapper.py`): `--annotator`/`--vadr-models`/`--vigor-db`/`--vigor-db-dir` flow through `_run_orthophyl` for every OrthoPhyl build. `_run_releaf` takes its `annotator` argument from the **target database's own** recorded value (never this run's CLI default) — a query ReLeaf'd onto a pre-existing viral DB is always re-annotated viral-style, mirroring how `tree_method`/`tree_data` are read from the matched DB rather than `self.*`. `--vadr-models`/`--vigor-db-dir` on the CLI still describe this run's own tool/DB locations on disk (not per-database), so `_run_releaf` reuses `self.vadr_model_libs`/`self.vigor_db`/`self.vigor_db_dir` when the matched DB is viral and raises a clear `RuntimeError` if they weren't supplied.
- **DB metadata chain**: `OP_database_tool.py --annotator prodigal|viral` writes `annotator` into `database_config.json` (`.get()` default `"prodigal"`, backward-compatible); `assembly_router.py`'s `_load_single_database`/`_route_to_releaf` read it back and surface it on the routing-decision dict, which the wrapper's `_parse_routing_results` carries into `releaf_batch` entries.
- `--genome-dir --annotator viral` auto-forces `self.skip_qc = True` (logged) since CheckM2 is bacteria-only — no need to also pass `--skip-qc`.
- **Not yet done**: the `viral_annot` micromamba env (VADR, exonerate, openjdk, diamond) and VIGOR4 release unpack in `Singularity.OP.v3.3.recipe`, and `tests/integration/test_viral_annotation.py` with committed `TESTER/viral_test/` fixtures — both need the actual VADR/VIGOR4 binaries to build/capture against, unavailable in a dev sandbox.

**Viral NCBI download** (`--taxon`/`--input` novel-taxon builds, automatic — no flag needed): a taxon whose NCBI taxid chain includes 10239 (Viruses) is detected via `is_viral_taxid` in `utils/taxon_assembly_gatherer.py` (`TaxonAssemblyGatherer.is_viral`, checked by rank-independent taxid membership, not a rank-name string — NCBI's root rank label for Viruses has changed over time) and routed to a completely separate download path instead of the bacteria-only CheckM2/assembly pipeline. `render_gtdb_lineage(..., is_viral=True)` forces the rendered lineage's domain slot to `d__Viruses` regardless of what NCBI's own rank names say.
- `utils/gather_viral_annots.py` downloads NCBI's **existing CDS+protein annotations** for the taxon (`datasets download virus genome taxon ... --include cds,protein,annotation`) rather than raw assemblies — there is nothing to annotate, so VADR/VIGOR4 never run on this path. It splits the pooled `cds.fna`/`protein.faa` into one `annots_nucls/<id>.fna` + `annots_prots/<id>.faa` pair per genome, grouping multi-segment records by isolate name when present (segmented-virus packages carry no BioSample), else by accession — meaning a genome's filename stem is not always a literal NCBI accession. `resolve_cds_strand` brute-forces frame×orientation against `protein.faa` per CDS because `cds.fna` does not reliably reverse-complement minus-strand/ambisense segments and some ranges start short of a ribosomal-frameshift junction (both confirmed against real NCBI Virus packages).
- `orthophyl_pipeline_wrapper.py`: `_download_genomes` branches to `_download_viral_genomes` for a viral taxon; `_run_taxon_create_mode_viral` is the dedicated create-mode path (`-a <nucls>,<prots>` instead of `-g` to `OrthoPhyl.sh`, `-n` computed from the CDS-file count, `annotator='viral'`/`input_type='annotations'` recorded on the new DB). Oversized viral taxa reuse the normal subsampling flow; `_stage_selected_viral_prots` symlinks each selected genome's matching `.faa` alongside its `.fna`. `--megatree` for viral taxa is rejected with an explicit error (out of scope).
- **Update mode** (`_run_taxon_update_mode_viral`, dispatched when the existing DB's `annotator == 'viral'`): there's no bacteria-style `assembly_summary.txt` for viruses, so this re-downloads the full current NCBI Virus set via the same `_download_viral_genomes` used at creation time and diffs by `annots_nucls/*.fna` filename stem against the DB's stored `assembly_accessions` — the creation-time ID scheme, not a raw NCBI accession, since segment/isolate grouping means they can differ. New genomes are already NCBI-annotated, so they're added via `_run_releaf`'s `annotation_dirs` param (`-a`, no VADR/VIGOR4).
- `_run_releaf` gained `annotation_dirs: Optional[Tuple[Path, Path]]` (mutually exclusive with `input_genomes`) precisely to let pre-annotated genomes flow through ReLeaf's pre-existing `-a` flag.
- **Router**: `assembly_router.py`'s `_route_to_orthophyl` detects `is_viral` (via `GTDBTaxonomy.get_rank('d') == 'Viruses'`) for a novel query and branches its advisory text — Step 1 points at `utils/gather_viral_annots.py` instead of `gather_filter_asms.sh`, Step 2's `OrthoPhyl.sh` invocation uses `-a` instead of `-g`. `is_viral` is surfaced on the routing-decision dict.
- **Not yet done**: the docs pass beyond this file, and a slow/network-marked end-to-end integration test (`--taxon "<small viral species>"` through to a tree, then a raw query routed to ReLeaf). CheckV-based QC for viral genomes remains unimplemented.

## Repo hygiene warnings

- Historically, files were **versioned by copy** rather than git (`.v2`, `.cmd_out3`, `_v2`, `.bak`, `.save`, `.1.1` suffixes). The live scripts have since been renamed to canonical names and the dead copies removed. If you find such suffixed twins reappearing, commit over the original instead — git is the version history. `dev_plans/` still references the old names historically; don't treat those as live paths.
- Large binaries live in the tree: `*.sif` Singularity images (multi-GB), `GPLv3.pdf`, `ncbi_dataset.zip`. `.sif` is gitignored. Do not commit new large artifacts.
- Test outputs under `TESTER/` (e.g. `FULLTEST_OUT.*`) are gitignored ephemera.

## Containers

Apptainer/Singularity is the only supported container path (the Docker recipe has been removed). `Singularity.OP.v3.3.recipe` is current; `Singularity.OP.v3.1.0.recipe`/`Singularity.OP2.2.1.recipe` are historical and not maintained. It uses micromamba with a base env (orthofinder, iqtree, fasttree, hmmer, mash, prodigal, trimal, raxml, ete3, pytest) and a separate `gather_genomes` env (checkm2, entrez-direct, ncbi-datasets-cli). Conda env spec: `orthophyl_env.2.2.1.yml`. Building requires `--build-arg checkm2_db_path=/path/to/uniref100.KO.1.dmnd` (no network fallback). The default `%runscript` just drops into a shell — use `apptainer exec <image> bash /opt/gits/OrthoPhyl/OrthoPhyl.sh ...`, not `apptainer run <image> <args>`. Full guide: `readmes/README_APPTAINER.md` (covers building, bind-mount semantics, running tests in-container, and moving databases between host and container).

**Megatree database layout**: a subclade/backbone DB (`is_subclade`/`is_backbone` + `parent_taxon`) nests under its parent taxon directory — `<database-dir>/<Taxon>/<Taxon>_db` (backbone), `<database-dir>/<Taxon>/<Taxon>_N_db` (subclades). Non-megatree DBs stay flat at `<database-dir>/<name>_db`. Every path a database persists (symlinks, sketch/members files, `orthophyl_runs.tsv` entries) is stored relative to a nearby anchor so a database built under one bind mount (host or container) works unmodified under another, as long as the bind is an identity bind (host path == container path). Databases predating this, or built with a mismatched non-identity bind, can be repaired with `python assembly_router/OP_database_tool.py --migrate [--strip-prefix PREFIX] [--dry-run]` — infers the old mount prefix, nests megatree DBs, rewrites paths relative to the new location, relativizes `orthophyl_runs.tsv`, regenerates the index, and reports (without deleting) dangling symlinks. Idempotent.

Other readmes live in `readmes/`: `README_APPTAINER.md` (containers), `README_USAGE.md` (worked examples for all three modes), `README_ADVANCED_FEATURES.md`, `README_PIPELINE_PHASES.md` (includes the routing workflow diagram), `README_TECHNICAL_REFERENCE.md`, `README_TROUBLESHOOTING.md`.
